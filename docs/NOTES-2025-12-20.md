# Notes – 2025‑12‑20 (Quick Enhancements)

These changes were put together quickly to unblock work. They’re meant as a solid foundation,
but **not** the final design. We should revisit and harden them later.

## Error handling for imports/bootstraps
- `schema:import`, `schema:import:functions`, `schema:bootstrap`, and `schema:bootstrap:seed`
  now catch per‑database errors.
- On failure, the CLI prompts to continue with the next DB (`[Y/n]`).
- A summary prints at the end listing successes/failures.

**Future improvements:**
- Add `--no-prompt` / `--continue-on-error` flags.
- Add per‑phase prompts inside bootstrap (functions vs modules vs seeds).
- Add retry with backoff for transient connection errors.
- Emit structured logs for CI usage.

## Context / Intent
The goal was to keep going when one DB is down, while still surfacing the error. This is a
fast‑path solution; it’s expected we’ll refine the UX and the configuration flags later.
